# Tabby TFTP

`tabby-tftp` adds firmware-friendly TFTP tools to [Tabby](https://github.com/Eugeny/tabby):

- TFTP client for uploads and downloads.
- A local, read-only TFTP server for bootloaders and serial-console firmware updates.
- RFC 2347/2348/2349 option negotiation (`blksize`, `timeout`, and `tsize`).
- Transfer progress, retry/cancel controls, server logs, and local IPv4 discovery.
- Server settings that survive closing and reopening the management window.

> TFTP has no authentication or encryption. Use it only on a trusted, isolated network.

## Serial-console firmware workflow

1. Open **TFTP File Transfer** from Tabby's toolbar.
2. Select **Firmware TFTP Server**, choose the firmware root directory, and start the server.
3. Copy the device-facing local IPv4 address shown by the plugin.
4. In the serial bootloader, configure the server address and request the firmware file. For U-Boot this is commonly `serverip`, `ipaddr`, and `tftpboot`.
5. Close the dialog when finished. Closing the dialog only hides the UI; the server keeps running until you stop it, its optional auto-stop timer expires, or Tabby exits.

The server is intentionally read-only: devices can download files from the selected root, but cannot upload or overwrite files on the computer.

## TFTP client

Use the **TFTP Client** tab to upload or download a file. The default port is `69`. A download requires a remote filename; for an upload, leaving the remote filename empty uses the local filename.

## Development

Requirements: Node.js 18 or newer and a Tabby-compatible Angular/toolchain environment.

```powershell
npm ci
npm run verify
npm run pack:plugin
```

`npm run verify` runs type checking, protocol/server tests, and the production bundle. The installable package is generated by `npm pack`.

## Local installation

Close Tabby, then install the generated `.tgz` into Tabby's user plugin directory and restart Tabby:

```powershell
cd "$env:APPDATA\tabby\plugins"
npm install C:\path\to\tabby-tftp-0.2.1.tgz --legacy-peer-deps
```

## Security notes

The server protects against path traversal and only serves regular files below the configured root directory. UDP port 69 and the negotiated transfer port must be allowed by the local firewall. See [SECURITY.md](SECURITY.md) for reporting security issues.
